# Brief client — Application Roadmap

## Contexte

Le produit du client grossit et l'organisation ne suit plus. Chaque jour, il note des idées de fonctionnalités, des bugs à corriger, des améliorations et de nouvelles features. Le produit compte plusieurs modules (facturation, onboarding, dashboard, etc.) et tout est mélangé : plus de 200 idées en vrac dans un Notion, impossibles à retrouver.

## Besoin

Une application pour **capturer rapidement les idées de features**, les **ranger par module**, les **prioriser**, puis **planifier leur réalisation par sprints**, en équipe.

## Fonctionnalités attendues

### 1. Capture des features

Chaque feature contient :

- un **titre** ;
- une **description** ;
- une **priorité** ;
- une **estimation de l'effort**, quand c'est nécessaire (facultative) ;
- le **nombre d'utilisateurs impactés**, pour aider à prioriser ;
- un **statut** pour suivre sa progression ;
- un **membre de l'équipe assigné**.

### 2. Modules

- Chaque feature est rattachée à **un module** du produit.
- On peut **filtrer** les features par module.
- Chaque module a une **couleur** choisie, pour s'y retrouver visuellement.

### 3. Sprints

- Un sprint est une période de travail d'**une ou deux semaines**, avec :
  - une **date de début** ;
  - une **date de fin** ;
  - un **objectif en une phrase** ;
  - un **statut** : en planification, actif ou terminé.
- On peut **assigner des features à un sprint** quand on décide de les traiter.
- Beaucoup de features resteront dans un **backlog sans sprint**, parfois longtemps.

### 4. Commentaires

- L'équipe peut **commenter les features** pour garder un historique des discussions et des décisions.
- Chaque commentaire indique **qui l'a écrit** et **quand**.

### 5. Équipe

- **4 personnes** pour l'instant.
- Chaque membre a un **prénom**, un **nom**, une **photo** et un **email**.
